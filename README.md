# Поиск кандидатов для услуг Авито

Задача — выбрать не более 50 объявлений из `benchmark_items.parquet` для каждого
запроса в `benchmark_queries.parquet`. Получена метриика **Recall@50 = 0.847859.**

## Как воспроизвести отправленный ответ

1. Положите `benchmark_queries.parquet` и `benchmark_items.parquet` в `datasets/`.
   Эти исходные данные не входят в Git-репозиторий.
2. Создайте окружение Python 3.12 и установите пакеты из
   [`requirements.txt`](requirements.txt). Для GPU нужна совместимая с вашей CUDA
   сборка PyTorch; поиск также работает на CPU или Apple MPS.
3. Запустите все ячейки [`inference.ipynb`](inference.ipynb) сверху вниз.

Ноутбук собирает готовый индекс и локальную E5-модель из частей в
`model_assets/` и вычисляет ответы. Обучение и доступ к внешним API для инференса не нужны.
Сборка архива происходит только при первом запуске. Если какая-либо часть
отсутствует или повреждена, ноутбук остановится с понятной ошибкой.

Для полного обучения с нуля нужны также `datasets/train.parquet` и
[`solution.ipynb`](solution.ipynb). Он строит модель, проводит валидацию и
сохраняет готовые артефакты в `notebook_outputs/`; после него можно отдельно
запустить ноутбук инференса. В Colab данные можно разместить в
`MyDrive/avito_datasets` — обучающий ноутбук скопирует их в рабочую папку.

## Данные, признаки и модель

`train.parquet` содержит положительные пары «запрос — выбранное объявление».
По ним оценивались переходы между локациями и вероятные подкатегории запроса.
Из текста запроса и объявления строятся BM25-признаки заголовка и описания,
символьное TF-IDF-сходство и сходство фильтров. География, подкатегория и
оценки исполнителя меняют вес кандидата, но не удаляют его жёстким правилом:
соседние локации и неочевидные категории иногда оказываются подходящими.

Для смыслового поиска используется открытая модель
[`intfloat/multilingual-e5-small`](https://huggingface.co/intfloat/multilingual-e5-small).
Её входы — текст запроса вместе с фильтрами и заголовок, параметры и описание
объявления. Эмбеддинги объявлений сохранены заранее. На инференсе получаем
эмбеддинг запроса и объединяем две выдачи по reciprocal rank fusion с равными
весами. В итоговый CSV попадают 50 уникальных `item_id` на запрос.

## Проверка качества и анализ ошибок

Для локальной проверки 1200 различных нормализованных текстов запросов
полностью исключались из обучения статистик. Из них 800 использовались для
подбора параметров, а 400 оставались отдельным holdout. Все положительные
объявления этих запросов добавлялись в валидационный корпус; их метки не
использовались при построении индекса. Recall@50 усреднялся по запросам.
На holdout лексический поиск дал **0.8800**, а итоговое объединение —
**0.88875**. Это локальная оценка; оценка чекера отправленного `answer.csv`
указана выше.

Разбор промахов показал три характерных случая: редкие разговорные запросы,
узкие услуги с несколькими близкими смыслами и объявления, которые точный
BM25 находил лучше семантической модели. Поэтому текстовый и смысловой поиск
объединены, а география и категория используются как мягкие поправки. Примеры
и покомпонентные метрики есть в обучающем ноутбуке.

Ноутбуки проверяют число строк, точное множество `query_id`, уникальность и
формат `item_id`, принадлежность объявлений исходному корпусу и повторно
читают сохранённый CSV. Порядок объявлений не влияет на метрику, но алгоритм
разрешения равных оценок зафиксирован для воспроизводимости.

## Состав проекта

- `solution.ipynb` — обучение, валидация, анализ ошибок и генерация ответа;
- `inference.ipynb` — автономный инференс из готовых артефактов;
- `model_assets/` — части архива модели и контрольные суммы;
- `answer.csv` — проверенный ответ;
- `requirements.txt` — версии библиотек для запуска.
