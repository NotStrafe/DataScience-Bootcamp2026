# Поиск кандидатов для объявлений услуг

`solution.ipynb` читает три Parquet-файла из `datasets/`, строит индекс,
проверяет Recall@50 на запросах train и создаёт `answer.csv`. Решение объединяет
BM25, символьный TF-IDF и мультиязычную модель
[E5-small](https://huggingface.co/intfloat/multilingual-e5-small). Для обучения
статистик используются только данные train; benchmark-запросы не размечены.
На отложенных запросах train Recall@50 вырос с 0.8800 до 0.8888 относительно
лексического поиска. Это локальная оценка, а не результат скрытой проверки.

Запустите все ячейки `solution.ipynb` сверху вниз в Python 3.12/3.13. В Colab
можно использовать T4. Если данные лежат в Google Drive, ноутбук ожидает их в
`MyDrive/avito_datasets` и копирует в `datasets/`. Открытая модель E5 загружается
один раз и затем сохраняется локально в `notebook_outputs/`.

`inference.ipynb` загружает сохранённый индекс, E5 и векторы объявлений из
`notebook_outputs/`, строит ответ по `benchmark_queries.parquet` и
`benchmark_items.parquet` и повторно проверяет формат CSV. Во время инференса
внешние API не используются. Чтобы воспроизвести результат с нуля, сначала
выполните `solution.ipynb`, затем `inference.ipynb` в той же папке.

`answer.csv` содержит ровно две колонки `query_id,answer`: одна строка на
каждый запрос, до 50 различных `item_id` через пробел. Ноутбуки проверяют
существование каждого ID в benchmark-корпусе и формат после повторного чтения
записанного CSV.
